# Codex Browser and Computer Use

- **Browser Use (`node_repl`)**: Use the `codex-browser` MCP service (in Claude Code: `mcp__codex-browser__js`, `js_reset`, `turn_ended`). Run `codex-browser-bridge --mode discover` once if needed to read `browser_client_url` (`file:///...`), then bootstrap in `js` via `const { setupBrowserRuntime } = await import("<browser_client_url>"); const agent = await setupBrowserRuntime();` (never `import "browser-client"`, and never paste raw Windows backslashes into JS strings). Keep REPL handles in `const`/`let` bindings, never `globalThis`.
- **Browser selection order**: Follow the installed Codex convention—when the user names a browser, call `agent.browsers.get("iab" | "chrome" | "edge" | "dot" | "extension")` and do not fall back if unavailable; when a URL is known, call `agent.browsers.getForUrl(url)`; otherwise call `agent.browsers.getDefault()`. Reserve `agent.browsers.list()` for troubleshooting (`agent.documentation.get("bootstrap-troubleshooting")` / `get("chrome-troubleshooting")`). Read `browser.documentation()` once without truncation.
- **Computer Use (`cua_repl`)**: Use the `codex-computer` MCP service (in Claude Code: `mcp__codex-computer__js`, `js_reset`, `turn_ended`). This unified runtime can also operate browser tabs. On the first `js` call (and after `js_reset`), execute exactly one native entry call, optionally assigning its result. Use `cua.getState()` when you need inventory; use the matching tab, browser, URL, or window entry when the target is known. Read the returned documentation and initial state before further calls; see [entry selection](references/native-computer-use.md#computer-use-cua_repl).
- **Efficiency, approvals & lifecycle**: Batch independent actions inside one `js` cell when intermediate results are not needed. Present native elicitation/approval requests to the user and respect their decision. Observe after input and never replay an action with an unknown outcome. Send `js` with only `completion_summary` once the CUA outcome is observed, when the installed schema exposes it. Call `turn_ended` at the host's actual turn boundary; completion summaries and `js_reset` do not replace this hook.
- **Tabs**: Follow the selected browser's native cleanup documentation. Only mark deliverable or handoff tabs (`markDeliverable` / `markHandoff`); marks are turn-scoped and must be re-applied when needed in a later turn. Unmarked agent-created tabs close on turn end; claimed user tabs are released and left open. Existing persistent IAB/Dot tabs stay open unless explicitly closed.

See [native runtime setup](references/native-computer-use.md) for bootstrap, troubleshooting, and CLI batch usage.
